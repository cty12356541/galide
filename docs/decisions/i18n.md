# i18n 决策记录

> v0.6 review 延期项的正式裁定。本文档只记录决策,不引入任何 i18n 基础设施。

## 决策

- **DSL 语法永久中文,不可本地化。** `gal` DSL 是产品身份与 canonical artifact 的一部分:`## 场景`、`角色: "台词"`、`[若:]`、`设:`(见 `src/shared/dsl/line-rules.ts`、`src/shared/dsl/lexer.ts`)不是界面装饰,而是决策树本身的行级语义。任何语言版本的翻译贡献都不得触碰 DSL 关键字。
- **UI 层暂不做 i18n。** 维持简体中文硬编码现状,`package.json` 不引入 i18n/intl 依赖,`src/renderer/index.html` 保持 `lang="zh-CN"`。
- **未来若启动,路径固定为两步:** 第一步只做字符串抽出,把 UI 硬编码中文收敛到消息目录(message catalog),zh-CN 为默认包;第二步才谈翻译。此路径不改 DSL、不改命令注册表 label 的 key 结构:`src/renderer/src/lib/command-registry.ts` 的 labels 已是注册表数据(`label: string` 字段),天然可抽出,抽出时 key 即 CommandId,不重命名。

## 理由

- **用户群即中文。** 产品定位为 AI-native galgame 制作 IDE(README 首行),核心创作者群在中文圈;`docs/agent-architecture.md`、`.style-spec/` 规约体系、全部错误信息(`src/shared/dsl/parser.ts` 的 `背景必须出现在场景块内` 等)均以中文为工作语言。
- **DSL 中文化是差异化,不是障碍。** 项目哲学是「文字游戏 = 语言意义选项的决策树」。创作者用母语书写剧本与条件,DSL 关键字与对白同文同种,认知摩擦最低。把 `设:` 翻成 `set:` 等于把产品退回「写代码」范式。
- **过早 i18n 是双重维护成本。** 在需求未被验证前,每加一个 UI 字符串都要同步维护消息目录与占位 key,而收益为零;字符串在快速迭代的 v0.x 阶段仍会大面积重写。
- **地基已经打好。** 命令注册表(`command-registry.ts`)把 label 集中为数据而非散落在 JSX,`.style-spec/` 规约体系为字符串集中化提供了落点。届时抽出是机械工作,不是架构改造。

## 触发条件

出现以下任一**可验证的客观证据**时,重启评估:

- GitHub issue / discussion 中非中文反馈占到可统计量级(例如持续数周、非零星单条);
- 下载/安装 telemetry 显示非 zh-CN 区域占比达到需要回应的水平;
- 目标发行平台或渠道对语言版本提出硬性要求。

触发后执行顺序不变:**先抽字符串到消息目录,再谈翻译**;任何翻译 PR 一律不得修改 DSL 关键字、parser/lexer 行规、`.gal` 文件语义。

## 非目标

- 不做 DSL 多语言语法(不存在 `set:` / `[if:]` 平行关键字)。
- 不做运行时语言切换 UI,直到触发条件满足。
- 不为 i18n 引入重型框架。届时评估轻量方案(如简单 catalog + lookup 函数),框架选型是触发后的独立决策。
